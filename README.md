# アドオンパックエディタ(Addon Pack Editor)

Tudur's Vehicle Mod (https://github.com/Tuduraw/tudursvehiclemod) 用のアドオンパックを、GUIで作成・編集するツールです。
日本語・英語に対応しています(「設定」→「言語 / Language」で切り替え)。


## 動作環境・起動

- Python 3.9 以上(tkinter を含むもの)。追加のライブラリは不要です(Pillow があれば HUD プレビューでテクスチャを表示)
  - Windows / macOS: python.org のインストーラーには tkinter が含まれています
  - Linux: `python3-tk` パッケージをインストールしてください
- 起動: `python main.py`

## 基本的な使い方

1. 「ファイル」→「新しいアドオンパック」で、パック名と名前空間を指定して作成します。
   作成場所にゲームディレクトリの `tudursvehiclemod-addons` フォルダを直接指定することでスムーズにテストすることもできます。
2. 「新規機体」で機体名(`tanks/t90` のように `/` でサブフォルダも可)とエンティティ種別を選びます。
3. フォームに値を入力して保存します。

### 機体データの編集

- エンティティ種別ごとに、その種別で使われる項目だけが表示されます。
- 項目名の横の `(default=…)` は、空欄のままにしたときに mod が使う値です。
  **空欄の項目は JSON に書き出されません**(mod の既定値がそのまま適用されます)。
- 項目名にマウスを乗せると、説明と記入例が表示されます。
- 数に制限のない項目(`seats`・`runways` など)は「＋ 行を追加」で増やせます。
- 「JSON手動編集」に切り替えると、JSON を直接編集できます。入力中に構文チェックが行われ、
  エラーのある行が赤く表示されます(カンマ漏れなどは原因となる前の行も表示)。
  構文エラーがある間はフォームに戻れません。
- フォームで扱えない項目(独自の項目、その種別では使われない項目など)は削除されず、
  そのまま保存されます。

### 武器ファイルの編集(「武器」タブ)

- 左の一覧から武器ファイルを選ぶか、「新規武器」で作成します(`guns/m2` のようにサブフォルダも可)。
  機体JSONの `weapon_name` にはファイル名部分(`m2`)だけを書きます。機体フォームの
  `weapon_name` 欄には、パック内の武器ファイル名が候補として表示されます。
- 選んだ `Type` で使われる項目だけが表示されます。表示される項目は、mod が実際に読むキー
  (107個)に限られます。MCヘリにあっても mod が読まないキーは表示されません。
- `CasWaypoint` などの繰り返し項目は行単位で追加でき、`AddMuzzleFlash` のような
  コンマ区切りの値は列ごとに入力できます。
- 「テキスト手動編集」では、mod の読み込み処理と同じ基準で各行を検査し、無視される行や
  既定値に置き換わる値を行ごとに強調表示します。例:
  - ウェイポイントの座標に小数を書くと、その行全体が無視されます(エラー)
  - 数値として読めない値は、黙って既定値に置き換わります(警告)
  - 同じキーが複数あると、後の行だけが有効になります(警告)
  - CAS / Carrier に必要な行が欠けていると、武器が機能しません(エラー)
- フォームで保存しても、手書きのコメント・行の順番・未知のキーはそのまま残ります。

### HUDスクリプトの編集(「HUD」タブ)

- 「新規HUD」で作成すると、標準テンプレート(方位テープ・照準・水平線・速度/高度/スロットル・
  耐久/燃料バー・選択中の武器・ロックオン、および失速・燃料低下・マニュアルモード・ギア・
  フリールックなどMCヘリにない機能の状態表示)が最初から入っています。
  「テンプレートを挿入」でいつでも入れ直せます。
- 入力中に mod の読み込み処理と同じ基準で構文をチェックします。例:
  - 不明な命令・引数不足の行は、mod に無視されます(エラー)
  - `If` の閉じ忘れはファイルの最後までが `If` の中になり、`If` の入れ子は外側の `If` を
    途中で閉じてしまいます(エラー)
  - 存在しない変数名は、mod ではエラーにならず 0 として扱われます(警告)
  - 書式指定子と値の数の不一致、パック内にないテクスチャ・呼び出し先など(警告)
- 右側のプレビューには、サンプル値を使った実際の描画結果が表示されます。要素をクリックすると
  その行へ移動します。「状態表示をすべてON」で、全状態の表示が同時に出たときの重なりや
  はみ出しを確認できます。
- 画面からはみ出す要素は赤い点線で示され、警告が出ます(保存はできます)。
  プレビュー画面は、GUIスケール後の大きさで選べます(720p 自動 = 427×240、1080p 自動 = 480×270 など)。
- Pillow(`pip install pillow`)がインストールされていれば、`DrawTexture` のテクスチャを
  実際の画像で表示します。なくても動作し、その場合は枠とテクスチャ名で表示します。

### ファイルの紐付け

- `model`・`texture`・`engine_sound` などの「…」ボタンでファイルを選ぶと、パック内に
  コピーされ、参照文字列が自動で記入されます。保存先のサブフォルダは自由に指定できます。
- `model` にパック内の OBJ を指定すると、右側に OBJ のパーツ(グループ)一覧が表示され、
  JSON でまだ使われていないパーツが上に並びます。`part` 系の入力欄の候補も同様です。
- 「ファイル」タブでは、パック内のファイルの追加・フォルダ作成・削除と、参照名の確認ができます。
- 武器・HUD・サウンド・HUD用テクスチャは mod がファイル名だけで参照するため、
  サブフォルダが違っても同じファイル名は使えません(重複時は警告されます)。

## プラグイン

`plugins/` フォルダ、またはユーザーフォルダ(`~/.tudursvehiclemod_addon_editor/plugins/`)に
置いたプラグインが自動で読み込まれます。アドオンMODが追加するエンティティ種別や設定項目を
ツールに表示させたり、独自の検証処理を追加したりできます。

同梱の `plugins/motorcycleaddon/` が見本です。

- `plugin.json` … プラグインの情報と、読み込むスキーマファイルの一覧
- `vehicle_motorcycle.json` … スキーマの追加(新しいエンティティ種別・項目・レコード)
  - `"inherits": "tudursvehiclemod:car"` で、車両用の項目もそのまま使えるようになります
- `plugin.py` … `register(api)` で検証処理(`add_validator`)・保存時の加工(`add_save_hook`)を登録
- `lang/` … プラグイン用の表示文字列

武器も同じ仕組みで拡張できます(スキーマの `"kind": "weapon"`)。アドオンMODが追加する独自の
武器タイプ(`Type = 名前空間:名前`)を `entity_types` に追加し、その武器タイプ専用のキーを
`extend` で `WeaponFile` に追加します。

詳しい仕様は `ape/plugins.py` と `ape/schema.py` の先頭の説明を参照してください。

## mod 本体の更新への追随(開発者向け)

項目の定義(`schemas/vehicle.json`・`schemas/weapon.json`)は、mod のソースコードと
ドキュメントから自動生成しています。mod 本体を更新したら、次のコマンドで再生成してください。

```
python devtools/gen_schema.py
python devtools/gen_weapon_schema.py
```

武器については、mod が読むキーの一覧と既定値を `WeaponStatsLoader` から取得し、
正式な表記・グループ・対象タイプ・列の構成・(ドキュメントにない項目の)説明文を
`devtools/weapon_meta.json` に手書きで持っています。mod 側でキーが増減すると、
`gen_weapon_schema.py` はエラーで停止して差分を表示するので、`weapon_meta.json` を更新してください。

- 項目名・型・必須/任意・既定値 … mod の Codec 定義(実際に JSON を読む処理)から取得
- 説明文 … `Readme_Vehicle*.md`(日本語)と `Another language/en_US/`(英語)から取得
- エンティティ種別ごとの表示 … 各項目を実際に読んでいるエンティティクラスから判定

自動生成で対応しきれない部分(説明文のない項目、種別の絞り込みなど)は
`devtools/schema_overrides.json` に手動で記述します。再生成しても消えません。
